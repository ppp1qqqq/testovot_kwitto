# AI_LOG

## Инструменты

Claude Code в облачной сессии на claude.ai/code. Ассистент писал код, тесты, Dockerfile и тексты, сам запускал pytest, ruff, сервер с curl-запросами и сборку в Docker. Других ассистентов не подключал.

## Как ставил задачу

Запрос был один, зато со всем контекстом: приложил PDF с заданием целиком и попросил сделать его аккуратно, перепроверять себя и опираться на тесты. Ещё попросил, чтобы README, этот файл и комментарии в коде читались как написанные человеком, без канцелярита. Пример из задания про рассрочку (`1990000` на 3 месяца даёт `[663334, 663333, 663333]`) сразу стал отдельным тестом.

## Где модель ошиблась и как это всплыло

Первый набор тестов (81 штука) прошёл с первого запуска, и это насторожило. Ассистент по очереди ломал код: переносил лишние копейки в конец графика, округлял скидку вниз, делал промокод чувствительным к регистру, разрешал лишний переход статуса, менял формат ответа 409. Тесты падали каждый раз, кроме одного. Если убрать поиск платежа по `Idempotency-Key`, всё оставалось зелёным, потому что дубль всё равно ловил unique-индекс в базе. Получается, ветку, где два одинаковых запроса приходят одновременно, не проверял ни один тест. Теперь есть тест, который имитирует такую гонку через monkeypatch.

Подпись вебхука сравнивалась через `hmac.compare_digest` на строках. На не-ASCII символах эта функция бросает `TypeError`, и запрос с `X-Signature: é` получал 500 вместо 401. Ассистент заметил это, когда перечитывал код перед README, и подтвердил запросом. Сейчас сравниваются байты, на это есть регрессионный тест.

Фильтр `GET /payments?email=` сначала сравнивал строки как есть. `EmailStr` приводит к нижнему регистру только домен, поэтому платёж от `Student@Example.com` по адресу `student@example.com` не находился. Всплыло при проверке в консоли, что именно возвращает `EmailStr`.

И мелочь: пустой `promo_code: ""` давал 422 «unknown promo code». Формы часто шлют пустую строку вместо null, так что теперь это считается «без промокода».
